---
title: Test and Live Modes
description: Test cards and credentials, how the two modes differ, and how to tell which one a transaction ran in.
---

SeerBit accounts operate in one of two modes. Which mode a request runs in is determined entirely by **which API keys you send** — the base URL is the same for both.

| | Test mode | Live mode |
| --- | --- | --- |
| Keys | Test public and secret key | Live public and secret key |
| Base URL | `https://seerbitapi.com` | `https://seerbitapi.com` |
| Money movement | None. Transactions are simulated. | Real funds move. |
| Availability | Immediately on sign-up | After your business is approved |
| Card details | [Test cards](#test-cards) only | Real cards only |

Because the base URL does not change, **swapping keys is what takes you live**. There is no separate sandbox host to point at.

Both key pairs live in the dashboard under **Settings > API Keys**. New accounts start in test mode, so you can build a full integration before submitting business documents; live keys appear once your business is approved.

## Test bank accounts

Test credentials for [bank account](/payment-methods/bank-account) and [transfer](/payment-methods/transfer) payments are issued per merchant account. Request yours from your SeerBit account team or via [support](https://seerbitteam.freshdesk.com/support/home).

## Test mobile money

Test MSISDNs for [mobile money](/payment-methods/mobile-money) differ by operator and country. Request the set for your markets from your SeerBit account team or via [support](https://seerbitteam.freshdesk.com/support/home).

## Confirming which mode a transaction ran in

The [payment status response](/online-payments/after-payments/verify-payment) includes a `mode` field:

```json
{
  "data": {
    "payments": {
      "mode": "live"
    }
  }
}
```

It reads `test` for simulated transactions and `live` for real ones. Check it if you are ever unsure which key pair a call used — most commonly when a payment appears to succeed but never shows up in your live dashboard.

## What carries over, and what doesn't

- **Transactions do not carry over.** A payment made with test keys never appears in your live transaction history.
- **Webhook subscriptions do not carry over.** Configure your notification URL separately in each mode — a test-mode subscription will not fire for live traffic.
- **Webhooks do fire in test mode**, so you can verify your handler end to end before going live.
